# Working on Storygro

Read [the handoff](docs/planning/HANDOFF.md), [architecture](docs/explanation/architecture.md), [workflows](docs/explanation/workflow.md), [product decisions](docs/planning/README.md), [implementation plan](docs/planning/IMPLEMENTATION_PLAN.md) and [migration record](docs/planning/MIGRATION.md). They are self-contained; no earlier chat is required. The [docs index](docs/README.md) routes by goal; [how we work](docs/explanation/how-we-work.md) covers decisions, model tiers and where files go. Pick methods and tools from the bank in [`production/toolkit.yaml`](production/toolkit.yaml) ([readable version](docs/reference/toolkit.md)); when you add a command, style, scene or method, add its entry and run `npm run docs:toolkit` — `npm test` fails otherwise.

- The product name **Storygro**, tagline, description, channels, and languages are settled. Do not restart naming research.
- This repository contains the extracted engine. Normal preview/render must not depend on a neighboring SlideCraft checkout. Asset regeneration for the historical example is an explicit optional exception.
- Retain `reel: 1`, `reel.yaml`, `.reel/`, and legacy environment aliases unless a migration is deliberately implemented and documented.
- Run `npm ci` and `npm run check`. Test actual rendering when changing the runtime, timing, scenes, audio, or browser capture. Report skipped checks and their concrete reasons.
- Scenes must support deterministic `draw(t)` and arbitrary seeking. Fix reusable modules, not one example by title or scene number. See [scene contract](docs/reference/scene-contract.md).
- Draft timing estimates are not final narration timing. Inspect rendered frames and listen to the audio before claiming a release is ready. Technical QA is not editorial approval.
- Implemented and verified: native 9:16 with platform safe areas, language variants, voice providers (`kokoro`, `qwen3`, `silero`, `chatterbox`; `yandex` implemented but not yet run against the live API) with Whisper alignment and a Russian stress layer (RUAccent homographs, rendered per engine), a voice bench (`production/py/voice_bench.py`), cut-paper scenes, carousels, `deliver`/`package` with manifests, trend signals with a per-idea watchlist and a research scan (GitHub, HF papers, Telegram, RSS, imported X digests; loud headlines set aside), screen recording (`capture` + `screencast`), brand profile and series, a manual publication ledger and metric snapshots, styles (`cartoon`, `cut-paper`, `editorial-collage`, `kinetic-type`) with `new`, a motion kit (springs, the music's beat grid in scenes and `snap` on sound effects, `format.blur` motion blur), local generated illustrations (`images`, Apple silicon) and reference transcripts (`transcript`). Planned, not implemented: API publishing to social platforms and automatic analytics. Do not describe planned features as working.
- Keep providers behind small interfaces. Rendering must remain usable without publishing accounts or a hosted service. Do not rewrite the engine just to adopt a competitor's stack.
- Preserve source provenance and third-party notices. Do not copy private client decks, credentials, licensed system fonts, caches, or `node_modules` into Git.
- The owner chose the SlideCraft licensing model: PolyForm Shield 1.0.0. Preserve LICENSE, COMMERCIAL.md and Required Notice lines; describe Storygro as source-available. Third-party model/asset terms remain separate.
- Stage explicit paths. Check current changes before editing; preserve unrelated user work.
- **Public Git media rule (owner, 2026-10-19):** never commit videos, audio, animated GIFs, archives, rendered PDF/PPTX, model weights or generated caches. Keep them in ignored local storage or release/object storage. Every indexed file must be ≤1 MiB; documentation/review preview images ≤300 KiB. Do not bypass this with `git add -f`, Git LFS, renamed extensions or an ad hoc allowlist. Source scripts, facts, provenance, licences and small previews belong in Git. See [media policy](docs/reference/media-policy.md).
- Install the local guard with `npm run hooks:install`; `npm run check` and CI enforce the same policy against **indexed blobs**, including forced additions. Use `npm run assets:fetch` to restore original off-Git render inputs from the checksum manifest. Never silently replace a differing local original.
- Social publication is a future explicit operation with a named destination and release. Local `deliver` and `package` are not publication.
- Every on-screen number lives in a data file with a quoted source (`sources.md`); never type numbers into scenes. Label predictions as predictions and keep the source's caveats.
- Narration is synthetic: disclose it in post texts. Never clone a real person's voice without their written consent. Model-provided voices may come from consented human performers; preserve accurate provenance rather than claiming no real person supplied the voice. Check model terms ([voices](docs/reference/voices.md)).
- **Russian voices (2026-10-21; the owner asked to compare Russian quality and use the conclusions):** new Russian episodes use the Qwen3 narrator at `speed: 1.12` with `stress: auto`; write brand names in Latin unless a test line says otherwise; mark homographs RUAccent cannot resolve. Names and hard words go into the shared dictionary `production/voices/lexicon-ru.yaml` (with a source), not into one script: before voicing, run `storygro stress <spec>`; for flagged words `--lookup --write`, then read the diff (2026-10-24, after stress errors in Месси, Платини, Париж, Кройф). The comparison and its numbers are in [voices](docs/reference/voices.md#russian-voices-compared); re-run the bench before switching engines. Before deleting anything local, read [local setup](docs/reference/local-setup.md).
- For the current `micro1-work-data` episode, the owner selected audition C: the original Russian Qwen3 reference, `speed: 0.96`, after rejecting Dima's youthful timbre. Preserve this episode's chosen voice; passing ASR does not establish the owner's preference for another timbre. Other existing episodes retain their own voice settings.
- New production content belongs in `content/videos/<id>/`; examples remain regression/reference material. Use `content/ideas/` and the `ideas`/`trends` commands for editorial selection. Signals are not proof of claims or a forecast of reach. Start a new episode from a style (`storygro new <folder> --style <id>`); see [use a style](docs/how-to/use-a-style.md).
- Generated pictures carry no text: headlines, numbers and labels are overlays bound to facts. Pictures stay out of Git (`shots/` is ignored); `images.json` records prompt, seed, model, licence and checksum. Keep transcripts and frames of other people's videos in ignored `private/`; take principles from references, never their characters, frames, script, music or voice.
- Changing scene code, theme, facts or assets resets the storyboard approval; re-render after the last change before packaging.
- **Content workflow (owner, 2026-10-20):** every episode folder keeps the script (`<lang>.reel.yaml`), `facts.json` with `_source`, `sources.md`, `images.json`, `review.yaml` and the generated plan `PLAN.<variant>.md` with `preview/plan/` strips — all in Git. Approvals go script → storyboard → release and are written by `storygro approve --step …` to `review.yaml`; an agent passes `--agent` (technical) and never records or edits an owner approval. Put questions for the owner in `review.yaml`, regenerate the plan (`storygro plan`) after every change and the tracker (`storygro tracker content/videos --md content/TRACKER.md`) before committing. Never edit `PLAN.*.md` or `TRACKER.md` by hand. See [content workflow](docs/explanation/content-workflow.md).
- Technical documentation and architecture labels use English; the product planning and handoff remain in Russian. User content keeps its intended language.
- Docs follow Diátaxis (`docs/tutorials`, `how-to`, `reference`, `explanation`; [ADR 0004](docs/adr/0004-docs-structure-and-media.md)). Pictures in `docs/` are English previews rebuilt by `npm run docs:media` from local renders, or SVG diagrams; Russian frames stay beside their content in `preview/`. `npm run check` includes `check:links`; fix every broken link or anchor.

Agent role documents describe responsibilities, not a requirement to spawn multiple agents.
