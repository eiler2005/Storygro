# Сканирование «видео как код»: пять публичных проектов

31 октября 2026. Задача: оценить пять публичных GitHub-проектов категории «video-as-code» на полезность для Storygro и найти **заимствуемые идеи** — редакторские референсы, чек-листы, приёмы работы с кадрами, — которые не требуют перехода на чужой стек.

Метод: страницы репозиториев прочитаны через web_fetch 31.10.2026; ничего не клонировалось, не устанавливалось и не запускалось. Счётчики (звёзды, коммиты) прочитаны на страницах GitHub в день скана и округлены как в интерфейсе; они описывают момент просмотра, а не динамику. Выводы — это оценка идей, не гарантия качества чужого кода.

Правила репозитория, которые ограничивают выводы: движок Storygro не переписывается под чужой стек; провайдеры остаются за маленькими интерфейсами; новые платные видеопровайдеры не добавляются; медиаполитика запрещает коммитить видео и крупные бинарные файлы.

## Пересечения с движком Storygro

**HyperFrames** ближе всех к нашей архитектуре: тот же принцип «детерминированный кадр через headless-браузер + FFmpeg», та же ставка на агентов. Фактически это независимое подтверждение выбранного Storygro подхода (сцены с `draw(t)`, произвольный seek, 1080×1920@30). Отличия: HyperFrames описывает тайминг data-атрибутами HTML и не требует React; Storygro держит сцены JS-модулями и `reel.yaml`. Переходить на их формат смысла нет — наш контракт сцены уже решает ту же задачу и покрыт тестами.

**Remotion** — главный идеологический источник всей категории: видео как чистая функция от номера кадра, `spring()`/`interpolate()`, `<Sequence>`. Storygro уже реализовал своё из этого же списка: motion kit (пружины, beat grid, `snap`), `format.blur`, `series-cover`/карусели как композируемые сцены. Их лицензия — полезное зеркало для нашего выбора PolyForm Shield: та же модель «source-available с коммерческими условиями».

**Manim** пересекается слабее (Python, математика, Cairo/OpenGL), но его словарь именованных анимационных намерений (`Create`, `Transform`, `FadeOut`) — это ровно то, что Storygro собирает в `production/toolkit.yaml` как банк методов, только на уровне кадра.

**remotion-video-skill** почти полностью повторяет путь, который Storygro уже прошёл и закрыл лучше: аудио-драйвен тайминг у нас — Whisper-выравнивание + словарь ударений, а не `ffprobe`-замер целого файла; «скилл для агента» у нас — рецепты `docs/how-to` + банк методов с тестом полноты. Проект полезен как подтверждение, а не как источник.

**video-shotcraft** закрывает пробел, которого у Storygro пока нет в явном виде: словарь приёмов кадра и чек-лист разнообразия планов. Наша текущая боль совпадает с их постановкой проблемы — правка владельца 2026-10-31 «два современных спецвыпуска слишком простые», требование нескольких связанных состояний действия и разных крупностей. У нас есть `reference-analysis` (разбор чужого видео) и правила серий, но нет карточек приёмов, на которые можно ссылаться при раскадровке.

## Заимствуемые идеи, по убыванию ценности

| # | Идея | Откуда | Что даёт Storygro | Цена переноса |
|---|---|---|---|---|
| 1 | **Карточки рецептов кадра + чек-лист разнообразия шотов** против «PPT vibe»: 10 категорий (Opening, Camera, Transitions, Typography, UI Entrance, Interaction, Data, Light & Emphasis, Rhythm, Outro), у карточки — timing, easing, choreography | shotcraft | Редакторский словарь для `DIRECTION.md` и раскадровок: «кадр строится вокруг глагола» получает именованный каталог (крупность, движение, переход, акцент светом). Чек-лист: N различных планов на бит, смена крупности по причине | Только документы: своя адаптация категорий под детский вертикальный мультфильм; чужой текст и код не копируем |
| 2 | **Отдельный документ эстетических QA-правил** (`aesthetic-rules.md`) + проверка кадров до релиза | shotcraft, hyperframes (lint-шаг в их скиллах) | Дополнить наш `check`-этап человеческим чек-листом кадра: читаемость на телефоне, контраст силуэта, отсутствие «постоянного зума одного кадра». У нас уже есть `still --guides`, feed/cover-preview — не хватает сформулированных правил, по которым смотрим | Один how-to/checklist документ |
| 3 | **Именованные примитивы намерения** вместо ручных кривых: `Create/Transform/FadeOut` как слова, которыми агент и человек говорят о кадре | manim | Расширить motion-kit-записи в `production/toolkit.yaml` именованными рецептами (например «появление предмета», «превращение схемы», «уход за границу»); сцены остаются нашими, меняется только словарь банка методов | Записи в toolkit.yaml + `npm run docs:toolkit`; движок не трогаем |
| 4 | **`frame.md` — дизайн-система, переведённая на язык видеокадра** (их формулировка: «your design system, ready for video») | hyperframes | Одна машиночитаемая спецификация серии: сетка 1080×1920, безопасные поля `reels`, линия feed-обрезки, палитра, правила титула/эмблемы — то, что сейчас разложено по ADR 0007, серия-библии и CSS стилей. Агент читает один файл перед генерацией кадров | Консолидация уже существующих правил в один документ; риск — рассинхронизация, нужен источник истины |
| 5 | **Скилл/рецепт как упаковка агентского workflow** (планирование → HTML → анимации → медиа → lint → preview → render) | hyperframes, remotion-video-skill | Подтверждает наш формат `docs/how-to` + toolkit; взять можно только явный lint-шаг перед рендером в рецептах серий | Минимальная; у нас уже есть `npm run check` |
| 6 | **`ffprobe`-кросс-проверка длительности озвучки** как дешёвая страховка | remotion-video-skill | У нас Whisper-выравнивание точнее; идея полезна лишь как автотест «финальная длительность ≈ сумма cue» в QA | Микроскопическая; скорее не нужна |

Явно **не** заимствуем: React/Remotion как рантайм, Python/Manim как рантайм, data-атрибутный HTML-формат HyperFrames, Lambda-рендер, платный MiniMax TTS, чужие демо-видео и тексты карточек (у shotcraft сами карточки описывают техники, «re-implemented from scratch» — берём словарь и структуру, не содержимое), чужих персонажей и кадры (правило репозитория о reference-материалах в ignored `private/`).

## Не-цели этого скана

- **Никакой замены стека.** Движок Storygro (сцены с `draw(t)`, headless-захват, `reel.yaml`) остаётся как есть; правило AGENTS.md «не переписывать движок под стек конкурента» применимо ко всем пяти проектам напрямую.
- **Никаких новых платных провайдеров.** Remotion-лицензия для компаний, MiniMax TTS, облачный рендер HeyGen/Lambda — вне рассмотрения. Все предложенные ниже эксперименты бесплатны и локальны.
- **Никаких бинарников в Git.** Демо-шоты, MP4 и скриншоты чужих проектов в репозиторий не попадают (медиаполитика: ≤1 МиБ на индексируемый файл, видео/аудио/GIF — только вне Git).
- **Не оценка качества чужого кода.** Мы не запускали ни один проект; заявления о продакшен-использовании и счётчики — это данные их страниц на 31.10.2026, не наши измерения.
- **Не одобрение выпусков.** Редакторские эксперименты ниже не заменяют цепочку script → storyboard → release approval.

## Рекомендация: два низко-рисковых эксперимента

**Эксперимент 1 — чек-лист разнообразия шотов как редакторский референс раскадровки.** Адаптировать категории shotcraft под наш формат: завести короткий справочник приёмов кадра (крупность, движение объекта, движение «камеры», переход, световой акцент, ритм) в `docs/how-to/` и раздел в шаблоне `DIRECTION.md`: какие приёмы использованы в каждом бите. Пилот — следующий эпизод Football Legends (FL-R1 остаётся главным фактором; чек-лист фиксируем как отдельный наблюдательный фактор, не приписываем ему метрики). Критерий: раскадровка показывает ≥3 различных читаемых плана действия на эпизод, каждый со сменой по причине; ревью владельца отмечает меньше замечаний «слишком просто». Стоимость: один документ + строка в шаблоне; движок, рендер и метрики не меняются.

**Эксперимент 2 — именованные рецепты движения в банке методов.** Взять из manim-словаря принцип «намерение как имя» и добавить в `production/toolkit.yaml` 3–5 записей-рецептов поверх существующего motion kit (пружины, beat grid, `snap`, `format.blur`): например «появление предмета», «превращение A→B», «акцент светом на факте». Каждая запись — как применять в наших сценах, без нового кода рантайма; если рецепт потребует хелпера, он реализуется как переиспользуемый модуль сцены по контракту `draw(t)`, а не точечно. Проверка: `npm test` (тест полноты toolkit) и `npm run docs:toolkit`. Критерий: следующий эпизод использует ≥2 именованных рецепта из банка вместо однотипного зума; это видно в раскадровке и на таймлайне.

Порядок: сначала эксперимент 1 (чистая редакторская работа, нулевой технический риск), затем 2. Оба — отдельные пилоты с одной главной гипотезой каждый, как требует наше правило экспериментов.

## Ограничения

- Счётчики и статусы прочитаны один раз, 31.10.2026, через web_fetch; страницы GitHub отдают их как в интерфейсе. У hyperframes ≈76,5 тыс. звёзд при относительно молодом публичном профиле — число записано как прочитано и требует перепроверки перед любыми решениями, где оно существенно.
- README — это самопрезентация: «used in production at HeyGen», «Make videos agentically» — заявления авторов, не наши измерения.
- Внутреннее устройство карточек shotcraft и скиллов hyperframes не читалось пофайлово (только страницы репозиториев); при реализации эксперимента 1 структуру категорий нужно сверить с их `references/` ещё раз и писать собственный текст.
- Manim находится в крупном рефакторинге и временно не принимает feature-PR; для нас это ничего не меняет (мы берём только словарь), но на его API как на стабильный референс опираться не стоит.
- Ни один вывод здесь не является одобрением сценария, раскадровки или релиза какого-либо эпизода.
