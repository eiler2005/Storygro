# Storygro — guide для первого результата

Это рабочий гайд к извлечённому движку и описание следующих рецептов. Он вдохновлён форматом [Ryze tutorials](https://www.get-ryze.ai/roles/tutorials): короткая задача, запрос агенту, понятный результат. Готовность каждого рецепта обозначена явно. Направление продукта — в [плане](IMPLEMENTATION_PLAN.md).

## 1. Начать с проверенного примера — доступно сейчас

Передайте агенту репозиторий и такой запрос:

> Прочитай AGENTS.md и docs/planning/HANDOFF.md. Подготовь локальный предпросмотр примера examples/slidecraft-launch/reel.yaml. Сначала используй оценочные тайминги без TTS. Покажи storyboard и укажи, какие материалы и проверки нужны для финального видео. Не подменяй исторические утверждения SlideCraft обещаниями Storygro.

Из корня проекта:

```sh
npm ci
npm run check
npm run storygro -- help
npm run storygro -- board examples/slidecraft-launch/reel.yaml --no-voice
```

Требования этого шага: Node ≥22.12 и Chrome/Chromium. Результат — `examples/slidecraft-launch/.reel/board.html` и `board.pdf`; в `.reel/board/` находятся снимки сцен. `.reel/` не входит в Git.

Для интерактивного просмотра:

```sh
npm run storygro -- preview examples/slidecraft-launch/reel.yaml --no-voice
```

CLI выведет локальный URL; на macOS откроет его автоматически. Space запускает/останавливает просмотр, стрелки меняют время. Ctrl+C останавливает сервер. Это проверка визуальной последовательности с приблизительными длительностями.

## 2. Голос, точный storyboard и видео — доступно для английского

Установите `uv`, затем из корня:

```sh
npm run setup
npm run storygro -- voice examples/slidecraft-launch/reel.yaml
npm run storygro -- board examples/slidecraft-launch/reel.yaml
```

Setup создаёт отдельное окружение `~/.storygro/venv`; модели могут скачиваться при первом запуске. При существующем подходящем окружении можно задать `STORYGRO_PYTHON=/absolute/path/to/python`. Если браузер не найден, задайте `CHROME_PATH`. Не отправляйте агенту реальные платные ключи в переписке; подключение будущих провайдеров должно идти через локальное окружение.

Просмотрите storyboard: в каждой сцене есть смысл, показанные числа соответствуют источникам, текст помещается, cue совпадают с озвучкой. Оцените звук и паузы в предпросмотре. Затем:

```sh
npm run storygro -- approve examples/slidecraft-launch/reel.yaml
npm run storygro -- render examples/slidecraft-launch/reel.yaml
npm run storygro -- deliver examples/slidecraft-launch/reel.yaml
```

`approve` фиксирует хеш сценария и data-файлов; их изменение сбрасывает согласование. Сейчас этот хеш не включает весь код сцен и каждый asset, поэтому он не заменяет проверку финального видео.

Результаты рендера — master/web MP4, stills/cards и QA в `.reel/`. `deliver` копирует существующие файлы в `~/Downloads/slidecraft-launch` или переданный каталог. Пока эта команда пропускает отсутствующие файлы; проверьте комплектность перед передачей. Она ничего не публикует в соцсетях.

Текущий ASR использует англоязычный MLX Whisper на Apple Silicon. Прохождение проверки совпадения слов не означает, что голос звучит естественно или что утверждения верны. Русский путь ещё требует реализации и проверки.

## 3. Создать собственный explainer — авторинг доступен, вертикальный RU/EN рецепт в работе

Пример брифа агенту:

> Сделай explainer по теме «[тема]» для «[аудитория]». После просмотра человек должен понять «[одна мысль]» и сделать «[действие]». Источники: [файлы/URL]. Начни со сценария и 5–8 смысловых сцен. Покажи механизм через повторяющиеся объекты и причинные изменения. Не выдумывай статистику. Целевые версии — RU/EN, 9:16, примерно 60–90 секунд. Сначала проверь, какие части этого формата уже поддерживает проект, и реализуй недостающее по плану.

Последовательность работы:

1. Собрать источники, отделить подтверждённые факты от авторской гипотезы.
2. Написать тезис, hook и цепочку сцен. У каждого движения должна быть объясняющая роль.
3. Создать отдельный каталог примера и `reel.yaml`; данные вынести в JSON. Следовать [writing-a-reel](../writing-a-reel.md) и [контракту сцены](../scene-contract.md).
4. Сначала проверить несколько ключевых кадров с `--no-voice`; после озвучки пересчитать timeline и storyboard.
5. Проверить читаемость на телефоне, переходы, субтитры, звук, источники и credits.
6. Отрендерить, просмотреть результат, сохранить фактические затраты и исправления.

Одного изменения `format.width`/`height` недостаточно: существующие сцены нуждаются в адаптации композиции. Не считать RU поддержанным только после изменения `voice.lang`.

## 4. Product demo — следующий рецепт

> Покажи одну реально работающую функцию [продукта]: исходная проблема → действие в интерфейсе → наблюдаемый результат. Используй публичный тестовый материал, сохрани исходники и запись. Не имитируй ещё не реализованные возможности.

Первый кандидат — публичный пример SlideCraft. Потребуется воспроизводимая запись или серия скриншотов, короткий сценарий и ясная подпись к результату. Новые команды для screen capture пока не реализованы; их нельзя обещать в инструкции как существующие.

## 5. Tutorial — следующий рецепт

> Научи пользователя выполнить [задачу] за несколько конкретных шагов. Укажи исходные требования, покажи действие, объясни ожидаемый результат и одну типичную ошибку. Подготовь сценарий, запись и текстовую версию инструкции.

Проверка: другой человек или агент повторяет действия в чистом окружении. Если результат зависит от внешнего сервиса, версии и ограничения фиксируются рядом с рецептом.

## 6. Пакет и серия — запланировано

После одного качественного выпуска: самостоятельная карусель, короткая версия видео, обложка, тексты и RU/EN варианты. Для серии нужны единый профиль бренда, повторяемые элементы и журнал тем. Первые несколько выпусков проверить вручную, прежде чем включать пакетную генерацию.

В текущем CLI нет команд `new`, `research`, `publish`, `analytics` или встроенного MCP-сервера. Пример запроса агенту описывает будущую работу, а не скрытые готовые команды.

## 7. Публикация и рост — запланировано

Назначения: Instagram и YouTube Shorts. Будущий publishing adapter должен работать с конкретным аккаунтом, одобренным release, расписанием и защитой от повторной публикации. Для первого подключения проверить актуальные возможности аккаунтов и API.

Аналитика связывает выпуск и его варианты с метриками в одинаковых окнах измерения. Агент предлагает следующий эксперимент, например изменить первые секунды или объясняющую метафору, и указывает, на каких наблюдениях основана рекомендация. Рост аудитории не гарантируется самим производством большего числа роликов.
