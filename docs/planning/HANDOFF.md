## Зафиксированные решения

**Storygro**, repository slug `storygro` (существующий URL имеет casing `Storygro`). Название больше не выбирать.

Description, дословно:

```text
A toolkit for AI agents to turn ideas into reels, videos, carousels, and social posts. Build your audience and grow your brand through content.
```

Tagline: **Turn stories into growth.** Public repository, без выбранной лицензии. `private: true` в package.json предотвращает случайную npm-публикацию и не означает приватный GitHub-репозиторий.

Начальная аудитория — свои продукты и личный бренд владельца, далее инструмент для других авторов и ИИ-агентов. Каналы — Instagram и YouTube Shorts. Языки — русский и английский. Цель — полный цикл исследования тем, производства, проверки, публикации и аналитики.

## Что есть в коде

Локальный TypeScript CLI, YAML-spec, восемь DOM-сцен, runtime с произвольным seek, Kokoro English TTS, timeline, storyboard HTML/PDF, approval по сценарию/facts, score/SFX/mix, MP4/stills/cards, технический QA, исторический пример SlideCraft. В корне теперь собственные package.json, lockfile и проверки.

Не реализованы полностью: native portrait explainer, русский голос/ASR, отдельные content-package/series модели, авторинг каруселей, social publishing и ростовая аналитика. Не выдавать будущие функции из description за текущие возможности. Не утверждать, что движок — Remotion: сейчас это DOM/JS + CDP/ffmpeg.

Следующий результат — реальный вертикальный explainer 9:16 с отдельными RU/EN версиями и воспроизводимым guide. Вопросы задавай только при действительно недостающих данных, правах или бюджете, продолжая независимые задачи.

## Первые практические действия

```sh
npm ci
npm run check
npm run storygro -- help
npm run storygro -- board examples/slidecraft-launch/reel.yaml --no-voice
```

Дальше: короткий оригинальный storyboard → адаптация нескольких нужных сцен под 9:16 → English baseline → проверка RU voice/ASR provider → два языковых варианта → просмотр/прослушивание → guide. Платные сервисы подключать после определения бюджета; для существующих локальных проверок ключи не нужны.

Готовность следующего этапа — файлы MP4 и исходники, которые другой агент может воспроизвести, а пользователь может прочитать на телефоне и понять. Одних unit-тестов или успешно завершившегося ffmpeg недостаточно.

## Что сохранить при изменениях

- Совместимость старого `reel.yaml`, cue-маркеров, `.reel/` и исторического примера.
- Разделение renderer / voice provider / publishing / metrics.
- Чёткие статусы проверок; skipped не означает passed.
- Источники, лицензии сторонних assets, уведомления к Liberation fonts.
- Отсутствие приватных deck-материалов, секретов, системных шрифтов и caches в Git.
- Отсутствие выбранной лицензии проекта до решения владельца.

Исходный SlideCraft имел посторонние изменения `.gitignore`, `biome.json` и untracked `reelcraft/`; не сбрасывать, не добавлять их в чужой коммит и не удалять донор автоматически. Роли `director`, `scene-builder`, `qa` — разделение обязанностей, а не инструкция запускать параллельных агентов.
