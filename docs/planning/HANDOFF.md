## Зафиксированные решения

**Storygro**, tagline **Turn stories into growth.**, description дословно:

```text
A toolkit for AI agents to turn ideas into reels, videos, carousels, and social posts. Build your audience and grow your brand through content.
```

Публичный репозиторий без выбранной лицензии (`private: true` в package.json только защищает от публикации в npm). Аудитория — продукты и личный бренд владельца, затем другие авторы и ИИ-агенты. Каналы — Instagram и YouTube Shorts. Языки — русский и английский. Название и позиционирование не обсуждать заново.

## Что не сделано и почему

- **Публикация и аналитика** (этапы 5–6) — нужны аккаунты владельца и выбор адаптера. Ничего не публикуется: `deliver`/`package` пишут локальные папки, `published: false`.
- **Product demo и tutorial** (этап 4) — нужна запись экрана; не начато.
- **Brand/Series** как отдельные сущности — пока не понадобились; эпизод и варианты — файлы.
- **Короткая версия 20–40 с** — не делалась.
- **Живое прослушивание** — агент проверяет речь распознаванием и метриками, но не слышит интонацию и ударения. Владельцу нужно посмотреть и послушать ролики на телефоне.
- Qwen3 и проверка речи требуют Apple silicon; на другой машине проверка речи помечается как skipped.

## Важные уроки

- В YAML запятая внутри `{ text: a, b }` разрезает текст — теперь это ошибка с подсказкой; тексты с запятыми брать в кавычки.
- Qwen3 читает «ИИ» в начале фразы как одно «и», а «ВШЭ» как «ВШ»: использовать `[ИИ](=и-и)` внутри фразы, полную форму в начале, аббревиатуры расписывать.
- Изменение кода сцен после approve делает рендер устаревшим; `package` откажется — перерисовать после последней правки.
- Safe-zone в профилях — оценки по рекламным гайдам и сторонним замерам; проверить загрузку на телефоне.

## Стартовый промпт

> Продолжай разработку Storygro в этом репозитории. Прочитай AGENTS.md, README.md, docs/architecture.md, docs/workflows.md и docs/planning/HANDOFF.md. Проверь git status и сохрани чужие изменения. Не выбирай название и не повторяй исследование заново. Начни с вопроса владельцу об отзыве на пример examples/ai-jobs (ролики RU/EN в релизе ai-jobs-2026-10-19) и внеси правки. Следующие шаги по плану: короткая версия ролика 20–40 с, профиль бренда и первая серия, затем — после того как владелец даст аккаунты и выберет способ — адаптер публикации с дедупликацией и статусами, и снимки метрик. Новые возможности описывай только после проверки рендером; результаты, источники и выполненные проверки сохраняй в Markdown. Вопросы задавай только про действительно недостающие данные, права, аккаунты или бюджет.

```sh
npm ci && npm run check
npm run setup:ru
npm run storygro -- board examples/ai-jobs/ru.reel.yaml
npm run storygro -- package examples/ai-jobs/episode.yaml
```

## Что сохранять при изменениях

- Совместимость `reel: 1`, `reel.yaml`, `.reel/`, cue-синтаксиса, `/rc/`, `npm run reel` и переменных `REELCRAFT_*`.
- Разделение renderer / voice provider / publishing / metrics; рендер работает без аккаунтов.
- Чёткие статусы проверок: skipped не равно passed; технический QA не равен редакционному одобрению.
- Источники и цитаты для каждого числа; уведомления о лицензиях шрифтов и моделей; раскрытие синтезированного голоса.
- Отсутствие приватных материалов, ключей, кэшей и `node_modules` в Git; отсутствие выбранной лицензии проекта до решения владельца.

Роли `director`, `scene-builder`, `qa` — разделение обязанностей, а не требование запускать параллельных агентов.
