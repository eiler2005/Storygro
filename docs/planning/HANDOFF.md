**Поправка — обрезка в ленте, 29 октября 2026:** владелец опубликовал пересобранного Мэтьюза ([DfFuW2QPoWb](https://www.instagram.com/p/DfFuW2QPoWb/)) и написал, что ролик «обрезается сверху». Причина: вне плеера Reels Instagram показывает тот же файл с обрезкой по центру — 4:5 в ленте (по 285 px сверху и снизу), 3:4 в сетке профиля, 1:1 в превью ссылки. Отступ `reels` в 220 px учитывал только шапку плеера: заголовок серии, плашки «50» и «4:3», карточка вопроса и голова Мэтьюза в двух кадрах пересекали линию ленты, хотя QA проходил. Теперь у `reels` и `vertical` верхний отступ 320 px, `still --guides` рисует линии 4:5 и 1:1, промпт `--target instagram-reels` держит головы ниже верхней пятой части кадра. Обложку и первый кадр выбираем так, чтобы заголовок и лица были в центральном квадрате. Мэтьюз по просьбе владельца переделан полностью: восемь картинок перерисованы с запасом сверху, обложка — первый кадр ([README выпуска](../../content/videos/football-legends-01-matthews/README.md#обрезка-в-ленте--29-октября-2026-вечер)). Другие опубликованные ролики не перерендерены; при следующем рендере их плашки сдвинутся вниз, поэтому раскадровку нужно проверить заново. **Загрузка в Instagram — настоящая причина обрезки, 29 октября 2026:** четвёртая публикация ([DfFzkZbhrdv](https://www.instagram.com/p/DfFzkZbhrdv/)) снова была обрезана. Правила ленты 4:5 сохранены: правильно загруженный Reels в ленте всё равно показывается как 4:5. QA теперь проверяет текст обложки в квадрате и пишет `feed-preview.jpg` и `cover-preview.jpg`. [Порядок загрузки](../how-to/instagram-without-cropping.md#upload), [ADR 0007](../adr/0007-instagram-reels.md).

## Что не сделано и почему

- **Публикация и аналитика** (этапы 5–6) — нужны аккаунты владельца и выбор адаптера. Ничего не публикуется: `deliver`/`package` пишут локальные папки, `published: false`.
- **Публикация через API** — нет. Есть ручной журнал `storygro publish` и снимки `storygro metrics` ([publishing](../reference/publication-ledger.md)): человек загружает, журнал фиксирует.
- **Avatar / generated footage** (этап 4) — не подключались; запись экрана (`capture` + `screencast`) готова.
- **Профиль бренда** `content/brand.yaml` — черновик агента; владельцу нужно проверить аудиторию, голоса и список нежелательных фраз.
- **Короткая версия 20–40 с** — не делалась.
- **Живое прослушивание** — агент проверяет речь распознаванием и метриками, но не слышит интонацию и ударения. Владельцу нужно посмотреть и послушать ролики на телефоне.
- Qwen3 и проверка речи требуют Apple silicon; на другой машине проверка речи помечается как skipped.

## Важные уроки

- В YAML запятая внутри `{ text: a, b }` разрезает текст — теперь это ошибка с подсказкой; тексты с запятыми брать в кавычки.
- Qwen3 читает «ИИ» в начале фразы как одно «и», а «ВШЭ» как «ВШ»: использовать `[ИИ](=и-и)` внутри фразы, полную форму в начале, аббревиатуры расписывать.
- Изменение кода сцен после approve делает рендер устаревшим; `package` откажется — перерисовать после последней правки.
- Safe-zone в профилях — оценки по рекламным гайдам и сторонним замерам; проверить загрузку на телефоне.

## Новое обязательное правило: медиа вне публичного Git

По просьбе владельца видео, аудио, GIF, архивы, экспортные PDF/PPTX и веса моделей запрещены в Git. Любой файл — ≤1 МиБ; превью для документации/ревью — ≤300 КиБ. `.gitignore`, pre-commit и `npm run check`/CI проверяют это; не обходить через `git add -f`, LFS или переименование расширения. [Политика](../reference/media-policy.md).

Из текущего Git убраны 12 файлов (18 372 137 байт); локальные копии и резервная копия в игнорируемом `private/git-media-cleanup-2026-10-19/` сохранены. Воспроизводимые исходные картинки и Qwen WAV загружаются командой `npm run assets:fetch` по `content/media-assets.json`, с проверкой размера/SHA-256; различающиеся локальные оригиналы не перезаписываются. Установить локальный hook: `npm run hooks:install`.

Сценарии, факты, источники, лицензии и маленькие strip-превью остаются в Git. Исторические коммиты/теги не переписывались; старые blobs по-прежнему в истории. GitHub Releases находятся вне Git-истории и не увеличивают checkout; они остаются публичными. Исторический рендер micro1 не изменён: исходные файлы побайтно те же, меняется их хранение.

Проверки хранения: media guard, TypeScript и **24/24 теста pass**; в изолированной чистой папке восстановлены 6/6 исходников с совпадением SHA-256, повторный запуск использует кэш, изменённый локальный оригинал сохраняется и вызывает отказ. После той чистки в индексе было около 9,34 МиБ файлов вместо 26,84 МиБ. Для изменения хранения видеорендер не требовался: renderer/voice/scenes и содержимое исходных файлов не менялись.

Позднее при выборе Qwen для micro1 добавлено седьмое назначение в `content/media-assets.json`: `content/videos/micro1-work-data/assets/voice/narrator-ru.wav`, тот же публичный референс, что в историческом `ai-jobs`, с тем же SHA-256. `npm run assets:fetch` восстановил его без записи аудио в Git. Новый полный Qwen-рендер и его QA описаны выше; остальные русские выпуски не переключались. Сохранять выбранный владельцем C, не возвращать Dima только на основании ASR. Ошибки, исправленные по ходу: ранний вывод «заглавная гласная помогает Qwen» по одному примеру не подтвердился на четырёх seed для «замка», затем стенд на 12 дублях показал 9/12 против 0/12 — решение принято по стенду; `stress: off` в YAML 1.1 читается как `false` (теперь в кавычках); рабочий процесс Chatterbox импортировал собственный провайдер вместо пакета (запуск с `-I`); RUAccent падал на словах вне словаря («Оупен») — добавлены нулевые `token_type_ids`, как в kokoro-ru.
