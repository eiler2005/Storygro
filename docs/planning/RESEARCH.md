# Storygro — исследование источников и аналогов

Дата проверки: **18 октября 2026 года**. Решения владельца находятся в [README.md](README.md), порядок реализации — в [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md).

## Метод и пределы выводов

Исследованы локальные файлы SlideCraft/reelcraft, README и отдельные исходные файлы публичных GitHub-проектов, файлы лицензий, документация Postiz и страницы пользовательских референсов. Ролик Instagram и гайд Ryze просмотрены через Chrome владельца.

Сторонние проекты не устанавливались, сравнительные рендеры не запускались. Наличие возможностей в README отмечается как заявление проекта; анализ отдельных файлов не равнозначен полной проверке работоспособности. Не измерялись стоимость, скорость производства, конверсия и рост аудитории. Отсутствие найденного аналога не доказывает отсутствие таких продуктов на рынке.

## 1. Что есть у нас

Исходный checkout на момент исследования: `/Users/DenisErmilov/aiprojects/slidecraft`. Пути ниже указаны относительно его корня.

После исследования владелец поручил немедленный перенос. Код из `reelcraft/` теперь находится в корне Storygro; конкретные изменения, устранённые зависимости и новые проверки описаны в [MIGRATION.md](MIGRATION.md). Ограничения ниже фиксируют исходное состояние до миграции.

### Основной донор: reelcraft/

Прототип v0.1, рассчитанный на будущее выделение в отдельный проект. Фактический стек: TypeScript/Node, обычные DOM/JS-сцены, Python для озвучки/распознавания/звука, Chrome через CDP, ffmpeg. React не требуется текущему движку.

| Возможность | Реализация / доказательство |
|---|---|
| YAML-сценарий, валидация, cue-маркеры, данные | `reelcraft/src/spec.ts` |
| Kokoro, метки слов, расчёт времени | `reelcraft/py/voice.py`, `reelcraft/src/timeline.ts` |
| Storyboard HTML/PDF, ключевые кадры, хеш согласования | `reelcraft/src/board.ts` |
| Музыка, эффекты, сведение, ducking | `reelcraft/py/score.py` |
| Предпросмотр и произвольный переход к моменту времени | `reelcraft/runtime/`, `reelcraft/src/serve.ts` |
| Захват кадров, MP4, stills и cards | `reelcraft/src/render.ts`, `reelcraft/src/cdp.ts` |
| Технический QA и проверка совпадения речи | `reelcraft/src/qa.ts`, `reelcraft/py/asr.py` |
| Руководство по сценам и режиссуре | `reelcraft/docs/`, `reelcraft/agents/` |

Существующие типы сцен: statement, logo-reveal, chat, stack, grid, spotlight, pins, end-card. Контракт сцен опирается на создание элементов и отрисовку по времени `draw(t)`.

Существующие CLI-команды: `voice`, `score`, `still`, `board`, `approve`, `preview`, `render`, `qa`, `deliver`. Они принимают `reel.yaml`. В CLI также есть режимы черновика и приблизительного времени без TTS. Промпты ролей в `agents/` не означают наличие автономного планировщика или полного редакционного сервиса.

Фактический порядок точного тайминга: текст → голос и метки слов → timeline → storyboard → согласование → финальный рендер. Предварительная раскадровка может использовать оценочные длительности; после записи голоса требуется пересчёт.

### Существующий launch-ролик

Публичный материал: `docs/media/launch/slidecraft-launch.mp4`.

Сохранённый локальный отчёт: `reelcraft/examples/slidecraft-launch/.reel/QA.md`.

Отчёт фиксирует 11 сцен, 65,18 секунды, 1920×1080, H.264/yuv420p, AAC, интегральную громкость −14 LUFS и прохождение перечисленных проверок. Во время исследования эти измерения повторно не запускались.

Пределы существующего QA:

- Проверка первого кадра измеряет контраст; она не оценивает силу начала ролика.
- Проверка Whisper сравнивает слова; она не подтверждает смысл, достоверность или естественность речи.
- Проверка чисел сверяет показанные значения с данными/разрешёнными значениями; она не проверяет первоисточники.
- В документации описан вывод красной панели при ошибке сцены. Финальный QA должен обнаруживать такую ошибку, а не принимать просто успешно закодированный MP4.

### Ограничения перед переносом

1. `reelcraft/` не отслеживается Git. Агент с одним клоном опубликованного SlideCraft может не получить этот код.
2. Перед началом документирования уже существовали изменения `.gitignore`, `biome.json` и весь `reelcraft/`. Не приписывать их текущей работе, не сбрасывать и не коммитить автоматически вместе с документами.
3. `reelcraft/examples/slidecraft-launch/assets.ts` импортирует внутренние модули SlideCraft, использует его примеры и копирует шрифты. Независимость ядра не означает независимость этого генератора.
4. Несколько сцен рассчитаны на горизонтальные размеры. Возможность задать width/height в спецификации ещё не обеспечивает качественную вертикальную композицию.
5. `py/asr.py` содержит `mlx-community/whisper-small.en-mlx` и `language="en"`. Нормализация текста в QA ориентирована на латиницу. RU и переносимость за пределы Apple Silicon требуют отдельной работы.
6. Пакет имеет `private: true` и `license: UNLICENSED`. Выбор владельца для Storygro — пока не назначать лицензию.
7. Отдельного зрелого набора тестов прототипа в исследованной структуре не найдено; нельзя переносить уверенность от тестов основного SlideCraft.

### Дополнительные материалы

- `scripts/launch/media.ts`: изображения для запуска продукта, social preview и иконка.
- `scripts/launch/story.ts`, `gif-story.ts`, `gif.ts`: сценарии/генерация launch-GIF.
- `scripts/launch/ph-watch.ts`: наблюдение за голосами, комментариями и позицией Product Hunt; не готовая аналитика Instagram/YouTube.
- [eiler2005/tg-media-saver](https://github.com/eiler2005/tg-media-saver): сохранение доступных медиаматериалов Telegram. Возможный вспомогательный инструмент подготовки исходников, не часть обязательного ядра.

## 2. Пользовательские референсы

### Product University: полный цикл

[Программа курса](https://productuniversity.ru/aigen#programma) связывает производство видео, адаптацию контента, публикацию и аналитику. [Страница вебинара о программируемом видео](https://productuniversity.ru/webinar/remotion) отдельно упоминает Remotion и HyperFrames.

Для Storygro значимы воспроизводимые процессы и обратная связь после публикации. Маркетинговые обещания курса по количеству материалов, окупаемости и росту не являются измеренными целями или гарантиями Storygro. Полная запись вебинара не просмотрена.

### Черняк: объяснение через визуальные метафоры

[Instagram, выпуск 41 серии «Экономическая машина»](https://www.instagram.com/reel/DeoOgL6i5tG/): вертикальное видео около 173 секунд. Изучены кадры и экранные титры по ходу воспроизведения; аудио отдельно не оценивалось.

Наблюдения: бумажные фактуры и вырезанные предметы, крупные подписи, повторяющаяся метафора руля, персонажи, изменяющиеся схемы, подсветка слов в субтитрах, связь со следующим выпуском и призыв переслать видео конкретному адресату.

Вывод для Storygro: нужны постоянные объекты и персонажи, движение, которое объясняет причинную связь, и сущность серии. Бумажный стиль — один пресет. Авторский сценарий и изображения не копировать; экономические утверждения ролика в исследовании не проверялись. По итоговому видео нельзя определить движок или происхождение голоса.

### Ryze: понятный инструмент и практический гайд

[Главная Ryze](https://www.get-ryze.ai/) — референс компактного бренда и понятного обещания результата. Итоговое название нашего продукта уже выбрано: **Storygro**.

[Гайд Ryze](https://www.get-ryze.ai/roles/tutorials) прочитан в браузере: работа через агента, GitHub, ключи сервисов, создание изображений/видео/озвучки, локальный предпросмотр, Remotion и пакетная обработка сценариев.

Переносимый принцип — короткие инструкции с примером запроса, видимым результатом и переходом от одного проверенного материала к серии. Storygro не обязан повторять набор сервисов Ryze. Утверждения о массовом выпуске и сохранении одинакового персонажа не проверены практическим запуском. Настройку секретов объяснять без просьб публиковать реальные ключи в переписке.

## 4. Вывод: что строить, что сравнивать, что подключать

| Часть | Предварительный выбор | Основание |
|---|---|---|
| Модель выпуска, серии, бренд, источники, версии | Собственная модель Storygro | Это связывает разные материалы и результаты публикации |
| Первый работающий рендер | Существующее ядро reelcraft | Уже есть локальный доказательный пример; меньше неизвестных при отделении |
| Альтернатива рендеру | Пилот HyperFrames | Близкая технология, потенциально меньше собственной инфраструктуры |
| Художественная библиотека | Свои сцены с изучением inkling/explainer-studio | Нужны конкретные метафоры и полноценная вертикальная композиция |
| Озвучка RU/EN | Адаптеры; выбор по коротким пробам | Текущий английский путь не доказывает поддержку русского |
| Публикация | Отдельный адаптер Postiz | Нет оснований сразу переписывать все платформенные API |
| Аналитика | Снимки доступных метрик с привязкой к выпуску | Набор данных зависит от платформы; сравнение требует контекста |

Postiz: [API](https://docs.postiz.com/public-api/introduction), [настройки Instagram](https://docs.postiz.com/public-api/providers/instagram), [аналитика канала](https://docs.postiz.com/public-api/analytics/platform), [аналитика публикации](https://docs.postiz.com/public-api/analytics/post). Требования подключения проверять на конкретном аккаунте; не обещать одинаковую доступность retention, saves, reach и других метрик.

Из исследованных проектов не подтверждён единый готовый продукт, который закрывает наши RU/EN-серии, несколько видов материалов, визуальную подачу референса, публикацию и измерение результата. Это основание для небольшого пилота и модульной интеграции, а не доказательство превосходства Storygro.

## 5. Чего пока не знаем

- Как выглядит одинаковый сценарий в нашем движке и HyperFrames после сопоставимого объёма правок.
- Сколько стоят и занимают производство, повторный рендер и локализация.
- Насколько хорошо конкретный голос произносит русский, английский и продуктовые названия.
- Какие данные реально вернут подключённые аккаунты владельца.
- Как выбранные форматы влияют на рост после серии реальных публикаций.

Следующий агент должен заполнить эти пробелы измерениями и артефактами, а не переносить рекламные цифры сторонних проектов в описание Storygro.
