# Research workflow for an agent

This is a reusable production procedure. Findings belong to `content/research/<topic>/`; the video references those findings from its own `sources.md` and `facts.json`.

1. Record the owner's brief and its provenance. Treat an attached post as a lead, not independent confirmation. Keep the content topic separate from the visual reference.
2. Check original announcements, product documentation and research. Save canonical URLs, publication dates, access date and the limits of the evidence. Record unavailable pages explicitly.
3. Classify each proposed claim: company statement, observed result, external study, author's inference, illustrative example, or unverified assertion. A budget commitment is different from spending; a price tier is different from an agreed payout.
4. Keep only the claims needed for one argument. Do not turn speculation into a factual hook. Current job adverts require current URLs if the script makes claims about hiring.
5. Store on-screen numeric values in the video's facts file with source IDs/URLs. The script uses bindings; keep qualifications visible near the figure.
6. Hand the evidence to the script/storyboard stage. Technical QA checks traceability and speech; it does not independently prove the source's claims.

There is no autonomous research command yet. The agent uses its browser/search tools and writes the research artifacts. A worked example is [micro1](../../content/research/micro1-work-data/README.md).
